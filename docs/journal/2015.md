Lessons from local solution headers and commit history; work means recorded Linux user-space instructions after subtracting empty-input startup.

## 2015/01

- idea: Stream a running sum, then switch to branch-free accumulation once the first threshold crossing is known.
- surprise: Checking the threshold on every byte blocked vectorization and lost to two passes.
- measured: 87,845 -> 74,362 work (1.2x); fully fused checks used about 20,000 more instructions than 00.

## 2015/02

- idea: Move the largest of three values aside and reuse the smaller pair's sum and product in a streaming parser.
- surprise: Separator dispatch still mattered after eliminating sorting and redundant arithmetic.
- measured: 492,685 -> 214,857 work (2.3x); conditional separators used 223,857.

## 2015/03

- idea: Share an open-address hash set between traversals, tagging coordinates by which traversal has visited them.
- surprise: Integer sanitizers reject unsigned shifts that discard set bits, so hash rotations need masking.
- measured: 118,739,612 -> 853,606 work (139x); sorting position arrays used 9,964,330.

## 2015/04

- idea: Cache invariant hash blocks, increment packed decimal digits, and batch unrolled hashes across independent lanes.
- surprise: Four lanes halved wall time but increased instruction work; the monolithic larger batch also failed the complexity gate.
- measured: 34,659,819,265 -> 3,222,796,879 work (11x); scalar candidate 6,870,898,235 versus four lanes 7,674,111,200.

## 2015/05

- idea: Fuse string predicates and retain each byte pair's earliest position to detect later nonoverlapping occurrences in constant time.
- surprise: Fixed-buffer streaming saved memory but performed more work than the fused line-buffered scan.
- measured: 1,674,816 -> 1,103,867 work (1.5x); fixed-buffer streaming used 1,225,025.

## 2015/06

- idea: Compress rectangle boundaries on both axes and update weighted cells with operations selected outside the inner loops.
- surprise: A row-band tree lost to dense rows, which still lost to compressing both axes.
- measured: 183,539,738 -> 31,455,654 work (5.8x); row-band tree 86,965,738 versus dense rows 67,315,973.

## 2015/07

- idea: Intern identifiers, evaluate dependencies with an explicit stack, and replay the recorded completion order after an override.
- surprise: Direct token scanning cut more work than changing the dependency traversal alone.
- measured: 205,944,857 -> 249,559 work (825x); token-library stack/replay used 433,038.

## 2015/08

- idea: Count representation changes directly and consume escape partners immediately, carrying only boundary state between buffers.
- surprise: A vectorizable second pass still lost to skipping consumed bytes in one streaming pass.
- measured: 178,040 -> 60,254 work (3.0x); two-pass exploration used 95,236.

## 2015/09

- idea: Merge paths with the same visited subset and endpoint, retaining only their minimum and maximum accumulated weights.
- surprise: Forward and backward subset DP were nearly tied; extracting shared helpers changed the measured totals.
- measured: 6,642,315 -> 231,574 work (29x); before extraction, backward DP 230,069 versus forward 229,796.
- technique: Extract recurring identifier and permutation helpers only after reuse appears, then benchmark again.

## 2015/10

- idea: Reuse two buffers for run-length transformations, emit counts directly, and count rather than materialize the final result.
- surprise: General-purpose count formatting dominated work; whole-run scanning also beat a streaming counter.
- measured: 8,437,318,472 -> 440,374,992 work (19x); streaming counter used 452,677,122.

## 2015/11

- idea: Search prefixes lexically while carrying constraint state and pruning prefixes whose remaining suffix cannot complete the constraints.
- surprise: Skipping forbidden ranges alone used more work than naive enumeration; prefix feasibility checks made the difference.
- measured: 201,997,683 -> 312,183 work (647x); forbidden-range skipping used 203,089,552.

## 2015/12

- idea: Fuse token processing and save running-sum checkpoints so excluded nested objects can roll back their contributions at closure.
- surprise: The lowest-work inline classification failed the complexity gate, so the retained implementation was slightly more expensive.
- measured: 1,726,302 -> 537,094 work (3.2x); inline classification used 530,602 but failed the gate.

## 2015/13

- idea: Combine reciprocal edge weights and reuse one subset-path table for cycle closure and complementary-path joins.
- surprise: Splitting complementary subsets avoided a second DP table; direct parsing further reduced work.
- measured: 7,985,422 -> 93,359 work (86x); before helper extraction, dual-table DP used 366,381.

## 2015/14

- idea: Build piecewise-linear timelines in blocks, cache them, merge pointwise maxima, and count ties against those maxima.
- surprise: Computing phase intersections cost more than direct simulation; caching timelines beat regenerating them.
- measured: 488,029 -> 142,361 work (3.4x); phase intersections used 509,844.

## 2015/15

- idea: Bound allocation prefixes, binary-search a unimodal residual objective, and solve the remaining linear constraint directly.
- surprise: Concavity removed an enumeration dimension, but monolithic pruning failed the complexity gate.
- measured: 27,576,793 -> 1,072,568 work (26x); residual linear sweep used 1,363,040.

## 2015/16

- idea: Parse fixed blocks, dispatch known field names, fuse predicates, and skip remaining fields once every predicate has failed.
- surprise: Block parsing beat both line-buffering variants while retaining constant memory.
- measured: 1,019,072 -> 147,074 work (6.9x); getline rows used 191,077.

## 2015/17

- idea: Fold items into a volume-indexed DP carrying total ways, minimum item count, and ways attaining that minimum.
- surprise: A separate count dimension was unnecessary because larger-count prefixes cannot improve the same extension.
- measured: 104,358,148 -> 35,080 work (2,975x); volume/count DP used 173,749.

## 2015/18

- idea: Pack grid rows into words and use balanced Boolean adders to count neighbors for many cells simultaneously.
- surprise: Balanced bitwise sums beat serial carries; padding alone left most of the per-cell work intact.
- measured: 86,950,140 -> 4,457,823 work (20x); serial bit carries used 4,777,823.
- technique: Carry shifts across word boundaries and pad boundary rows to remove repeated edge checks.

## 2015/19

- idea: Hash canonical edit descriptions and use a checked rule-weight invariant to replace derivation search when applicable.
- surprise: Trimming common prefixes and suffixes deduplicated results without constructing them; an extra suffix table was unnecessary.
- measured: 2,579,623,473 -> 955,520 work (2,700x); extra suffix table used 985,314.
- technique: Verify an invariant's preconditions and retain an exact chart parser for grammars outside them.

## 2015/20

- idea: Build divisor sums with a linear sieve, bound the search with a qualifying composite witness, and stop capped updates when complete.
- surprise: Lower instruction work came with higher peak memory than early-stop delivery sieves.
- measured: 422,174,405 -> 73,974,125 work (5.7x); early-stop delivery sieves used 224,332,276.

## 2015/21

- idea: Enumerate unique combinations and precompute winning thresholds for each defense total instead of simulating repeated interactions.
- surprise: Threshold lookup beat even the closed-form alternative that divided twice for every combination.
- measured: 122,813 -> 17,147 work (7.2x); per-combination divisions used 24,717.

## 2015/22

- idea: Search exact states with A*, deduplicate them, and use circular priority buckets justified by bounded priority increments.
- surprise: A consistent optimistic cost reduced search work beyond uniform-cost buckets without needing a comparison heap.
- measured: 183,248,501 -> 2,803,548 work (65x); uniform-cost buckets used 3,300,410.

## 2015/23

- idea: Decode opcodes once and fuse an exactly recognized loop into direct arithmetic, pairing dependent recurrence transitions.
- surprise: Enum dispatch helped, but eliminating dispatch inside the recognized loop saved substantially more work.
- measured: 280,468 -> 16,242 work (17x); enum dispatch used 51,937.
- technique: Require an exact instruction-pattern match before replacing interpreter steps with a specialized recurrence.

## 2015/24

- idea: Bound sorted subset searches, look up the final required weight, and verify the remainder while skipping equivalent bucket loads.
- surprise: A knapsack optimum still needed a feasible remainder certificate and lost to bounded search with final-weight lookup.
- measured: 45,160,468 -> 251,707 work (179x); knapsack with certificate and fallback used 517,774.

## 2015/25

- idea: Compute a diagonal index with a triangular sum and jump through a multiplicative recurrence using modular binary exponentiation.
- surprise: Left-to-right exponentiation saved a leading square but still used more instructions than right-to-left exponentiation.
- measured: 374,860,455 -> 3,496 work (107,226x); left-to-right exponentiation used 3,539.
